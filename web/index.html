Classify why your agent failed. Recover intelligently.

Your framework knows that the agent failed. It doesn't know why — so every failure gets the same blunt response. triage wraps any async agent callable, classifies the failure, and routes each type to the recovery that actually fits it.

The problem

A retry that carries no new information repeats the same mistake.

Agent failures don't come with clean discriminators. The same RuntimeError can mean nine different things depending on what the agent was doing before it failed — and the signal lives in the trajectory, not the exception string.

Without classification

One response for every failure

Retry from scratch, or give up. The agent that called a tool which doesn't exist calls it again. The agent that blew its context window gets handed the same oversized context. Recovery is a coin flip that costs a full run.

With triage

The failure type selects the recovery

A wrong tool call gets the tool manifest. A transient 503 gets exponential backoff. A detected loop gets a new plan, not another lap. A blown context gets replanned against a compressed one.

Taxonomy

Nine failure types, grouped by the recovery they need.

The grouping is the point. Some failures heal on any retry, so classifying them buys you nothing. Others only recover if the retry carries the right hint — that group is the entire reason this library exists.

Immediate  ·  routing-sensitive

Only the matched hint recovers these.

WRONG_TOOL_CALLED

The agent called a tool that doesn't exist. Retry with the correct tool manifest injected.

SCHEMA_MISMATCH

Output didn't parse, or arguments didn't validate. Retry with the schema hint.

CONSTRAINT_IGNORED

The agent violated a constraint it was given. Replan with the constraint restated.

Delayed  ·  structural

A retry repeats the mistake; the plan has to change.

LOOP_DETECTED

The same tool and input repeated across recent steps — including across an agent handoff. Replan, or roll back.

PLAN_INCOMPLETE

The agent stopped with subgoals outstanding. Resume from the subgoal it abandoned.

CONTEXT_OVERFLOW

The window filled. Replan against a compressed context rather than the same one.

Minor  ·  self-healing

Any retry recovers these. Classification adds nothing — which is worth saying out loud.

EXTERNAL_FAULT

A 429 or 5xx from something you don't control. Back off and retry.

TIMEOUT

A deadline passed. Back off and retry, or replan if it keeps happening.

Untriaged

The safe default when the classifier doesn't recognise the failure.

UNKNOWN

Falls through to your default policy. Escalates rather than guessing.

Usage

A policy is a mapping from failure type to strategy.

You write the policy once. triage classifies each failure, looks up the matching strategy, and executes what that strategy asks for — retry, replan, roll back to a checkpoint, resume from a subgoal, suspend, or escalate.

Any async callable
import triage
from triage.strategies.retry import retry_with_tool_manifest, backoff_and_retry
from triage.strategies.replan import replan
from triage.taxonomy import Step

async def my_agent(task: str, *, record_step, update_state, **kwargs):
    data = fetch_data(task)
    record_step(Step(index=0, action="fetch", tool_output=data))
    update_state({"data": data})
    return process(data)

policy = triage.FailurePolicy(
    WRONG_TOOL_CALLED = retry_with_tool_manifest(max_attempts=3),
    EXTERNAL_FAULT    = backoff_and_retry(max_attempts=5),
    LOOP_DETECTED     = replan(hint="Try a different approach."),
    default           = triage.FailurePolicy.escalate_by_default(),
)

agent = triage.Agent(my_agent, policy=policy)
result = await agent.run("your task")
Or wrap a framework
import triage
from triage.adapters.langgraph import wrap_langgraph
from triage.strategies.retry import backoff_and_retry
from triage.strategies.replan import replan

from my_graph import graph  # a compiled StateGraph

agent = wrap_langgraph(graph, policy=triage.FailurePolicy(
    EXTERNAL_FAULT = backoff_and_retry(max_attempts=3),
    LOOP_DETECTED  = replan(hint="Try a different approach."),
    default        = triage.FailurePolicy.escalate_by_default(),
))

# The adapter reads graph.astream_events() and records each
# tool call and model turn as a Step for you.
result = await agent.run("Summarize the latest earnings report.")

Measurement

What it detects, and what it misses.

Routing only helps if the classifier gets the type right. So here is the held-out number, split by group — because the aggregate averages two groups whose value to you is opposite, and quoting it alone would flatter the result.

RulesClassifier  ·  corpus D

Held out, scored once. Zero API calls.
Self-healing  external_fault, timeout Recall is good here — and classification buys nothing over a blind retry.
86%6 / 7
Routing-sensitive  wrong_tool_called, schema_mismatch Only the matched hint recovers these. This is the value proposition, and this is the number.
8%1 / 12
Precision Every miss falls through to UNKNOWN and your default policy — never a confident wrong guess.
100%0 misroutes
The finding that produced those numbers: a tuning pass added roughly fifteen patterns reverse-engineered from an earlier corpus's exact misses, closed all thirteen of them, and moved routing-sensitive recall on a fresh corpus by nothing at all. Ollama, MCP, CrewAI, Semantic Kernel, HuggingFace and OpenRouter each phrase “no such tool” differently. Self-healing recall held at 86% for the mirror-image reason: that group clusters around HTTP status codes and the words “timeout” and “rate limit” — a small vocabulary SDKs happen to share.

HybridClassifier  ·  same corpus

Rules first, LLM only on UNKNOWN. Closes the recall gap — at a price.
Routing-sensitive recall Semantic classification reads the meaning rather than matching a literal string.
83%10 / 12
Misroutes The 100%-precision guarantee does not carry over. One entry that genuinely has no answer was correctly left UNKNOWN by the rules and overturned into a confident wrong guess.
15%3 of 20

If you are evaluating triage today: on a stack whose error strings match the patterns in rules.py — OpenAI, Anthropic, LangChain, botocore, azure-core, Mistral, Cohere, Groq, LiteLLM, Vertex AI, LlamaIndex — routing works as shown. On any other stack, expect most tool and schema failures to land in UNKNOWN and fall through to your default policy: safe, but no better than the retry loop you'd have written yourself. Install

Core is three dependencies. Everything else is opt-in.

anyio, pydantic, and the standard library. No framework imports anywhere in the core — adapters are extras, and they fail at import time if the optional dependency is missing rather than at runtime.

pip install triage-agent

That gets you RulesClassifier, all nine failure types, every recovery strategy, in-memory checkpoints, and both adapters' source. Add an extra when you need the dependency behind it.

triage-agent[anthropic] LLMClassifier via Claude
